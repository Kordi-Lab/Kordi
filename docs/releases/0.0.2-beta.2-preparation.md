## What's New

Beta 2 makes conversations easier to pick up and more stable to navigate,
with individual photo actions on iPhone and more capable local agents on Mac.

- **Keep your place in longer conversations.** Desktop history loads more
  steadily, media previews reuse loaded images, and unread replies stay in
  order. iPhone chats reopen more reliably and handle scrolling and keyboard
  transitions more smoothly.
- **Expand agent details without losing your place.** iPhone trajectories open
  below their header without jumping to the end of the reply, and short chats
  stay above the composer when reopened.
- **Work in the folder you chose.** Local agents retain your workspace across
  follow-ups and resumed sessions. Owner-only macOS application automation is
  now available.
- **React to individual photos.** Each iPhone photo has its own reaction and
  deletion controls. Message menus preserve formatted text, emoji, and
  expanded content.
- **Pick up conversations with less clutter.** History recovery avoids repeat
  uploads and preserves original dates on iPhone. Read messages clear their
  delivered iPhone notifications, and Agent subsessions open more reliably.

This is draft release copy. Publish the photo-action highlight only after the
server rollout and live mutation checks below pass. The desktop in-app summary
uses four curated highlights for this exact version. Full GitHub and updater

## TestFlight: What to Test

Draft for iOS 0.0.2 (2), after release qualification:

- Reopen long chats and Agent subsessions, scroll older history, jump to the
  latest message, and open or dismiss the keyboard. Check that your reading
  position stays stable and replies remain above the composer.
- Expand and collapse agent trajectories, including in short chats. Check that
  details stay below the header and opening them preserves the tapped position.
- Long-press text and individual photos. Try photo reactions and deletion,
  repeated menus, and returning to the keyboard. Check that each action affects
  the selected photo and that formatted content keeps its layout.
- Open chats from notifications, read their messages, and return to
  Notification Center. Check that read notifications disappear while newer
  unread messages and unread threads remain.
- Revisit synchronized older conversations. Check their original dates and
  watch for repeated history or stale deleted photos.

### Device acceptance follow-up

Device acceptance identified pending iPhone messages appearing before confirmed
history. The final display pass mixed local draft times with server timestamps.
The follow-up tracked in [#1521](https://github.com/Kordi-Lab/Kordi/issues/1521)
keeps unconfirmed outgoing messages after confirmed history, preserves their
order through acknowledgements and retries, and keeps related agent progress
with its request. Original history dates remain unchanged.

Three synthetic display-model regression tests failed on the original code.
All 64 selected iOS tests passed after the correction, including rapid-send,
retry, imported-history, agent-presentation, and native send/motion coverage.
The corrected candidate requires fresh qualification and signed client builds
before publication; the earlier local artifacts must not be relabeled.

### Limits and remaining release gates

Publication is on hold while additional main-branch fixes are incorporated.
The trajectory follow-up in [#1528](https://github.com/Kordi-Lab/Kordi/issues/1528)
preserves the tapped position during expansion, clips details below their
header, and stabilizes short-conversation entry. Local device-test builds do
not lift the publication hold or authorize a TestFlight upload.

1. Review and merge this preparation change, require candidate CI, and pin the
   exact merged source. The existing main CI run must finish successfully.
2. Compare deployed server, runner, and schema with the pinned candidate in
   the authorized product phase. The change range includes server changes and
   migration `0091_chat_attachment_actions.sql`. Do not infer deployed state
   from this source review. Deploy only an actual missing backend diff.
3. Before exposing live per-photo actions, verify migration `0091`, the new
   attachment routes, photo reactions, scoped deletion, and private visibility.
   Older-server errors must not fall back to deleting or reacting to the whole
   message. Keep additive tables and visibility filtering during rollback
   after private hides have been written. See [photo action rollout](../ios-photo-actions.md).
4. Complete APNs end-to-end notification delivery, routing, and read cleanup
   acceptance. The latest notification PR adds `message_sequence` to new push
   payloads; its device QA used local notifications. Apply the runbook's
   background/locked-iPhone call acceptance gate for relevant APNs changes.
5. Recheck the desktop tag, GitHub release, immutable object keys, and iOS
   build `2` availability in their release phases. Resolve signing, team,
   capabilities, and Apple agreements before building or uploading.
6. Complete signed artifact, privacy, notarization, updater, publication,
   rollback, and TestFlight processing gates in the
   [standard release order](../development/dual-platform-release-runbook.md).

History-recovery fixes prevent further replay; they do not remove existing
duplicate server rows. Any historical data repair is a separate scoped task.
Desktop cache limits do not establish a hard process-memory cap; long-session
memory observation remains follow-up work from #1496. Legacy iOS notifications
with unknown read state remain until that state can be resolved; immediate
cross-device removal while the app is suspended is not promised.
