# Kordi 0.0.2 Beta 6 release preparation

Prepared on October 26, 2026. Status: source preparation; not published.

| Platform | Version | Build or tag |
| --- | --- | --- |
| macOS | `0.0.2-beta.6` | Proposed tag `V0.0.2.beta6` |
| iOS | `0.0.2` | Proposed build `8` |

The previous published desktop release is
[Beta 5.2](https://github.com/Kordi-Lab/Kordi/releases/tag/V0.0.2.beta5.2),
published on October 15, 2026. Its historical preparation document predates
publication. This candidate's changelog covers changes after that published
tag; shared documents, connectors, and the original account memory features
are not new in Beta 6.

This preparation does not reserve an iOS build number, create a tag or GitHub
release, publish updater objects, upload to App Store Connect, or change a
production feature flag. The final candidate must be a pinned merged commit.

## What's New

The exact Beta 6 entry in the root changelog is the canonical release-note
list. The in-app summary highlights four areas:

- Grounding profile cards, selected sources, references, rooms, and Nearby.
- Richer contact profiles and a channel chooser for groups in Contacts.
- Memory categories, source review, card assignments, and imports on Mac.
- iPhone video sharing, the Classic chat theme, and consistent avatars.

Cooperative and Personal agent controls are included in source. Product
availability remains subject to the deployed capability and rollout settings;
this preparation does not enable group automation.

## Qualification recorded

- The merged prerelease fixes passed required CI, including group/channel
  navigation, Grounding discovery and retry, source error handling, and
  canonical avatar rendering.
- Grounding card creation and the hosted Support response were exercised
  against the canonical product service with its Google Cloud model service.
- Both connected iPhone models have the current production avatar renderer.
  A saved randomized avatar was confirmed to match across devices.
- The additional iOS avatar refresh fix passed 89 XCTest and 5 Swift Testing
  tests covering profiles, avatar identity, conversation catalogs, wire cache,
  and initial state. Its integration test fails on the original source and
  passes after the fix, including a busy refresh, transient failure, and repair
  on a later empty sync poll. Final candidate inclusion requires its merge.
- The currently deployed backend is compatible with the source baseline;
  canonical health, schema, and service readiness passed. Compare the final
  pinned candidate with the deployed backend before deciding whether a
  deployment is needed.

## Candidate acceptance

Before public availability, record results for the exact candidate:

- Build a Grounding card from selected sources on Mac and iPhone, inspect
  references, change its selection, and verify sharing-off behavior.
- Exercise room membership, QR scanning, and physical phone pairing.
  Foreground pairing success does not establish camera QR or background
  discovery behavior.
- Complete physical background discovery, suspended permission changes, and
  APNs receipt and notification-tap acceptance tracked in
  [#2100](https://github.com/Kordi-Lab/Kordi/issues/2100).
- Save an avatar on one device and check the chat list and an already-open
  contact profile on the other, including after reconnecting.
- Open a group from Contacts on Mac and iPhone, choose a non-first channel,
  and verify immediate selection with preserved membership and names.
- Exercise new video sharing, contact media, memory assignments, and permission
  recovery on the platforms that changed.
- Recheck local Calendar discovery on Mac. The earlier empty Calendar result
  remains unresolved; distinguishing errors from empty results does not prove
  that calendars are discovered.
- Review the remaining long-session Mac memory investigation in
  [#1753](https://github.com/Kordi-Lab/Kordi/issues/1753). The earlier HTTP
  resource fix does not establish resolution of the residual growth.

## Distribution gates

Follow the [standard release pipeline](../development/dual-platform-release-runbook.md)
from the merged candidate. Record each phase independently.

1. Qualify and merge the implementation and release metadata, then pin the
   exact source commit. Confirm every desktop version source and both iOS
   app and share extension report the selected versions.
2. Recheck tag, release, and immutable object-key availability. Confirm iOS
   build `8` is unused in App Store Connect before the iOS distribution phase.
3. Verify final backend compatibility. Deploy only if relevant backend,
   runner, schema, configuration, media, or APNs inputs changed.
4. Build and verify macOS signing, notarization, stapling, Gatekeeper, privacy,
   updater signatures, DMG layout, and publisher dry-run checks.
5. Publish only within an authorized publication phase, including exact-byte
   verification, conditional promotion, rollback rehearsal, and GitHub mirroring.
6. Archive and export the production iOS scheme with the approved team,
   production APNs and App Group. Verify signatures, versions, privacy,
   dependency provenance, and artifact digests before any upload.
7. After an authorized upload, confirm processing and internal TestFlight
   visibility. Upload success alone is not release completion.

Do not relabel the existing build 7 phone previews as build 8 artifacts. Any
source change after qualification requires a newly pinned candidate; already
published immutable artifacts require new version or build identifiers.
